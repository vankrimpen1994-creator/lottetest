## What's in it

**The page** carries the strategy: the goal, the three-account split, the three pillars, the
B2B/B2C judgement call, daily engagement, measurement benchmarks, the nine questions for Rik,
and a sources toggle.

**The database** (`Content Calendar — Posts`) holds the nine posts, one row each:

| Property | Why it's there |
|---|---|
| Post, Date, Week | The grid |
| Account | Mark / Founder 2 / company page |
| Audience | B2B or B2C — the split is visible at a glance |
| Pillar | Enforces the three-pillar discipline |
| Format | Text / Carousel / Single image / Video |
| Status | Draft → Pending approval → Approved → Scheduled → Posted |
| Visuals needed | Checkbox, so design work is filterable |
| Hook | The first line, scannable without opening the row |
| Needs from client | What's blocking that specific post |

Three views: **📅 Calendar** (by date), **👤 By account** (board), **✅ Approval** (board by status).

**Every row opens into a full page** with: why this post exists, the pain point, the full copy
in a code block (Notion gives it a one-click copy button), the visual brief, and sources.
W1-01 also carries the ten carousel slides as a table.

## How Rik reviews it
Comment directly on the copy — highlight and hit 💬, same as Google Docs — then set **Status**
to Approved or Not approved. That's stated in the callout at the top of the page.

## Why Notion and not the spreadsheet
A flat sheet forced 397 stacked rows and no per-post detail. The Notion database gives one row
per post with the full draft behind it, filterable by account, audience and status — which is
what a content calendar actually needs to be.
